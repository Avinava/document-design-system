# Follow outside diagram practice by principle, and keep charts in chart-design

**Type:** Architecture decision record · ADR 005
**Status:** Accepted
**Date:** 2026-11-13
**Supersedes:** none

## Context

The `diagram-design` skill adapts its editorial standard from an outside
open-source diagram project: deletion as the highest-quality move, one accent,
hairlines over shadows, and label geometry that is verified. No code is copied.
The credit lives only where `AGENTS.md` allows it: `THIRD_PARTY_LICENSES.md`, the
skill's credits and the "Built on" sections of the README and the site.

That project keeps adding diagram forms and checks, and the repository has not
recorded how far it follows. Separately, `chart-design` owns quantitative charts
and `diagram-design` owns arrangements, and some shapes sit on the boundary.

## Decision

We will follow outside practice by principle and in our own vocabulary. A form is
added to `diagram-families.md` only when its layout is new, so a candidate that
is a variant of an existing form is folded into it. Forms that exist for
decoration, such as exploded and axonometric views, are declined. Names, files
and scripts use this repository's terms and copy nothing. The baseline we
followed, and the version we last caught up to, is recorded in
`THIRD_PARTY_LICENSES.md` and nowhere else.

Exploded and axonometric views are declined for three reasons, recorded in the
folded and declined table of `diagram-families.md`. First, depth and perspective
encode nothing that grouping and a labelled boundary do not already say, so the
extra dimension is decoration. Second, an oblique or isometric projection cannot
sit on the 4px grid, which means the geometry checks (overlap, bounds, label
clearance, text fit) cannot verify it. Third, the result reads as product
illustration, and a figure in this system answers one reader question with one
accent. A reader who needs to see parts of one assembly uses an architecture map
or a layer stack instead.

Charts stay in `chart-design`. A quadrant stays a diagram, donut and gauge are
listed as forms to avoid, and a chart form is added only when a shipped document
uses it.

## Consequences

Benefits:

- The credit has one location and the policy is checkable against it.
- The diagram catalog grows by layout, not by the number of names the outside
  project uses.
- Readers keep one rule for choosing between a chart and a diagram.

Costs:

- Catching up is a deliberate, reviewed step, not an automatic sync.
- Some outside forms will be absent here by design.
- Every new form needs its own specimen and checks before it is accepted.
