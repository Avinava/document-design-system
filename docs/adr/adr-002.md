# Make voice tokens part of the theme contract

**Type:** Architecture decision record · ADR 002
**Status:** Accepted
**Date:** 2026-11-13
**Supersedes:** none

## Context

`core/tokens.md` requires colour, three font stacks and two radii. Heading sizes
are fixed in `core/base.css`, and the hero title size is a fixed `clamp()` in
`core/document-patterns.css`. Themes can therefore recolour a document and swap
an interchangeable sans face, but cannot change scale, weight, density or
ornament. Documents in different themes read as the same document in different
paint.

Moving a hard-coded value into a theme only helps if every theme must supply it.
A token with a default in base CSS would override the theme, because base CSS
loads after the theme.

## Decision

We will treat voice as part of the token contract. Type scale, weight and
tracking, density and ornament (rule widths, eyebrow treatment) become required
tokens in `core/tokens.md`, declared by every theme, including
`brand-template.css`. Base CSS derives its sizes and spacing from them and
declares no fallback values on `[data-theme]`. `scripts/audit_theme.py` reads
the required set from `tokens.md`, so the contract and the check stay one list.

## Consequences

Benefits:

- Themes can differ in scale, density and ornament, not only colour.
- A missing token fails the audit instead of rendering a half-themed page.
- Heading sizes stop being repeated in two stylesheets.

Costs:

- Every existing theme must be edited to declare each new token.
- Adding a token later touches every theme again.
- Tokens computed from other tokens must be declared on `:root, [data-theme]`,
  as the derived colour tokens already are.
