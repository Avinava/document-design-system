# Let each pattern own its opening

**Type:** Architecture decision record · ADR 003
**Status:** Accepted
**Date:** 2026-11-13
**Supersedes:** none

## Context

Every body currently opens with the same `.doc-hero` shell class: an accent
rule, an eyebrow, an h1, a lede and a bordered `.doc-meta`. Most of the
`html[data-pattern]` rules in `core/document-patterns.css` change only
`--doc-max`, so patterns differ little on the first screen. The first screen is
where the reader decides what kind of document this is.

The module registry in `core/document-patterns.md` already says which modules a
pattern may use. It has no equivalent for how a pattern begins.

## Decision

We will give each of the eleven patterns one distinct opening, recorded in an
`## Openings` table in `core/document-patterns.md` next to the module registry.
`scripts/catalog.py` will parse the table, and a check will fail when a body does
not use its own pattern's opening parts or when two patterns share an opening.
Openings are built from the shell's hero parts and use semantic tokens only.

## Consequences

Benefits:

- A reader can tell a decision brief from an incident report from the first
  screen.
- The opening is declared once, in the same place as the other pattern rules, and
  checked like them.

Costs:

- Every body in `templates/types/` and `templates/composed/` needs its hero
  markup rewritten.
- A composed document must pick an opening instead of inheriting a default.
- Openings must hold at 390px and in print, which adds render-check cases.
