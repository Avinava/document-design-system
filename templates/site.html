Documents that get a reader to a decision

Every document turns two dials. The pattern sets how it reads: where the answer sits, what repeats, what the reader does last. The theme sets how it sounds. Turn one and the other stays where it was.

Six skills for writing documents, reports, diagrams, charts, decks and brand themes, all drawn on one set of design tokens. Writing lands as Markdown in your repository; designed HTML, when you ask for it, needs no JavaScript and prints.

One engagement, end to end

Every example here comes from one fictional engagement. Northwind Ingestion runs every producer through one shared queue, and that queue keeps stopping all of them at once. RFC 014 splits it in two. Each stop below is the document a reader needed at that moment, dated as the engagement dates it.

Two dials: how it reads, how it sounds

The pattern fixes reading order — @@PATTERNS_WORD of them, from decision to brief, on the Patterns page. The theme sets type, colour and density through tokens. Neither touches the facts, and changing the theme never changes the structure.

When no type fits, compose

@@TYPES_WORD_CAP presets cover the usual engagement documents. When a request falls between them, start from the reader's question. It names the pattern, and the pattern names the modules the page may use.

Figures that stay true

Diagrams and charts are SVG drawn on the page's own tokens. These four are inlined, so they follow this page's theme and its dark mode. The waterfall refuses to render if a total is not the sum of its steps.

Mermaid and draw.io files are inputs: their structure is imported and redrawn. SVG on tokens is the output. Open the figure gallery.

What's new in 0.5.0

  • Compose when no type fits

    Route by the reader's question to a pattern, then build from the modules that pattern allows. The platform primer is the worked example; a shape composed three times becomes a preset.

  • Figures you can check

    Change view, deployment map and dependency graph join the diagram forms; a waterfall bridge joins the charts. Geometry and rendered bounds are checked, and draw.io or Mermaid files import as structure.

  • One catalog, pinned tools

    Types, patterns and modules are read from the type files and one module registry. The authoring toolchain is pinned to exact versions, and the attribution is corrected.

Built on

Readers need nothing installed: a delivered document is HTML and SVG. These run only on the machine that writes it, pinned to exact versions.
