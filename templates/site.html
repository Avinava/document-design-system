Reader's question → pattern

The pattern fixes reading order: where the answer sits, what repeats, what the reader does last. It is declared with data-pattern.

The other @@OTHER_PATTERNS_WORD patterns, and all @@TYPES_WORD presets, start from the reader's question on the Patterns page. When no preset fits, the pattern alone is enough to compose one.

Audience → theme

The theme sets type, colour and density through tokens, declared with data-theme. Changing it never moves a section. Compare every theme.

Both sit on the same facts

Every example draws on one ledger, and every claim carries its evidence state. A missing fact stays unresolved; it is never invented.

Markdown is the canonical form. Designed HTML is built from the same title and facts, and a test fails when the two disagree.

One engagement, four acts

Northwind Ingestion runs every producer through one shared queue, and that queue keeps stopping all of them at once. RFC 014 splits it in two. Each act is a job readers are doing; each document is the shape their question needed.

@@STOPS_WORD_CAP documents, @@USED_PATTERNS_WORD patterns, @@VOICES_WORD voices, one ledger of facts. A shape composed three times becomes a preset; that is the only way the catalog grows.

Figures that stay true

Diagrams and charts are SVG drawn on the page's own tokens. These four are inlined, so they follow this page's theme and its dark mode. The waterfall refuses to render if a total is not the sum of its steps.

Mermaid and draw.io files are inputs: their structure is imported and redrawn. SVG on tokens is the output. Open every figure.

What's new in 0.5.0

  • Compose when no type fits

    Route by the reader's question to a pattern, then build from the modules that pattern allows. The platform primer is the worked example.

  • Figures you can check

    Change view, deployment map and dependency graph join the diagram forms; a waterfall bridge joins the charts. Geometry and rendered bounds are checked, and draw.io or Mermaid files import as structure.

  • One catalog, pinned tools

    Types, patterns and modules are read from the type files and one module registry. The authoring toolchain is pinned to exact versions, and the attribution is corrected.

Built on

Readers need nothing installed: a delivered document is HTML and SVG. These run only on the machine that writes it, pinned to exact versions.
