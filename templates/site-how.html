From a question to a document

document-design-system is a plugin for Claude Code. A plugin adds commands to it; this one adds commands for writing documents: decision papers, runbooks, postmortems, status reports and @@MORE_WORD more kinds.

You say who will read the document and what they need to decide or do. The plugin picks the document's shape, writes it from facts that can be checked, and, if you want a designed page, gives it a voice that suits the audience.

What you type

There are two ways in, and they end in the same place. Neither needs you to know the vocabulary on this page.

A command

One command per kind of document, named for it. Use compose when no kind fits.

/document-design-system:runbook
/document-design-system:postmortem
/document-design-system:compose

Plain words

What happens to a request

Seven steps, in this order. The only step that depends on you is the first; the choice that matters most is the third, and it comes from the reader's question.

Every claim says how sure it is

A document is only as good as the facts under it. The plugin marks each claim a reader might not be able to check with one of five evidence states, and a fact it does not have stays an open question instead of becoming a guess.

Two choices, kept apart

A document's shape and its voice are decided separately. Change one and the other stays put, which is why a postmortem can be re-skinned without moving a section, and why two documents with the same look can still read in different orders.

Axis onePattern

Four documents, four reading orders. Each opens differently because its reader arrives with a different question. The thumbnail is the first screen.

Axis twoTheme

One proposal, written once, in three voices. The sections, the order and the facts are identical; type, colour and density are not. The third is a client's own brand, turned into a theme.

A third, smaller switch is width. A designed page uses its pattern's reading column unless you ask for a full-width page; then maps, tables and figures use the whole screen while prose keeps its comfortable line length. It changes neither the pattern nor the theme, and the wide architecture page is the same document as the architecture page.

Install it

You need Claude Code. Inside it, add the catalog and install the plugin; the name appears twice because the @ reads "from".

/plugin marketplace add Avinava/document-design-system
/plugin install document-design-system@document-design-system

Then type one of the commands above, or just describe the document you need. Prefer plain skills without the plugin system? Each of the @@SKILLS_WORD skills installs on its own with npx skills add Avinava/document-design-system.
