Design handoff · operator overview

Show whether ingestion is healthy without requiring dashboard archaeology

Build a read-only overview that names the current state, exposes queue lag and shed behavior, and routes operators to the existing runbook rather than inventing control UI.

For: Platform UIFile: operator-overviewAs of: 2026-08-18Owner: Platform

Primary user flow

  1. Open the overview from the on-call page.
  2. Read the global written status and last refresh time.
  3. Identify the queue with rising lag or shed count.
  4. Open the existing runbook; do not operate the service from this page.

02

Required states

acceptance

Happy

All queues written as healthy; lag and shed values visible.

Idle

No recent events; explain that zero traffic is not a failure.

Loading

Reserve layout and announce refresh without presenting stale values as current.

Partial data

Show available queues and name the missing source.

Error

Written failure, last known update, retry behavior, and runbook link.

Recovered

Success label with recovery time; avoid celebratory animation during incidents.

04

Responsive, content, and accessibility rules

non-negotiable
  • Desktop uses a two-column queue grid; mobile uses one column in the same information order.
  • Never truncate queue names, status labels, timestamps, or error messages.
  • Announce status changes through a polite live region; do not announce every unchanged refresh.
  • Meet AA contrast and keep visible focus on every link.
  • Use real headings and lists; cards do not replace document structure.

Acceptance: all six states render at 390 and 1440 pixels, status survives grayscale, keyboard order is stable during refresh, and every failure path still exposes the runbook link.
