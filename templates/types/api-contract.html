Events API: accept once, identify clearly, retry safely

Use this page to understand producer behavior. The machine-readable source remains openapi/events.yaml; this companion explains the decisions callers most often get wrong.

Operations

POST

/events

Validate and accept one event. Returns 202 with the event ID and acceptance status.

GET

/events/{id}

Look up one event by opaque ID. Returns 200 or 404; this is not a list endpoint.

Caller conventions

Identity
Send a stable opaque id. Reusing an accepted ID must not create a second warehouse row.
Trace
Send X-Request-Id; the service echoes it on every response.
Retry
Retry only responses whose body sets retryable: true, using bounded exponential backoff.
Version
Breaking changes move to /v2. Adding an optional field is not a breaking change.

Known specification drift

Not shipped: OpenAPI and the current implementation still return 503 on queue overload. The 202 + INGEST_SHED specimen is proposed by RFC 014 and must not be treated as current until the source file changes.
